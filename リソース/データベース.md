# データベース

データベースの用途、使い分けなど。

## 一般的な検索

### MySQL

- オープンソース
- RDBMS
- SQL言語

一番スタンダードなデータベースであり、非常に強力な検索能力を持つが、データ量に応じて動作速度がボトルネックになる。
ボトルネックとなるデータ行数は100万件〜と言われており、昨今はビッグデータとは言わない程度でもかなりのデータ量になるため特にSaaS用途では難しい場面がチラホラ出てくる。

### PostgreSQL

- オープンソース
- RDBMS
- SQL言語

機能が豊富でネイティブUUIDの対応やViewの機能が強力。
MySQLよりも検索能力が高い代償に、INSERT時にオプティマイザが色々考える必要があるためCPUコストは高くなる。ここはトレードオフであり、一般的にはスタンダードとして選択されている。
自分的にはPostgreSQLの能力を活用した実装の必要に出会ったことがなく、それならばMySQLの方が軽くて良いんじゃないかと思います。

### SQLite

- オープンソース
- RDBMS
- SQL言語

こちらはサーバーとしてではなく、アプリケーションに組み込んで実装するよう設計された軽量なRDBMSのライブラリです。
Androidには標準ライブラリとして入っています。
特徴としては型を指定する必要がなくNoSQL的に使用できるので、用途が合えばかなり使えると思います。
構造的に小規模なデータしか扱えないのがネックです。

## NoSQL

### Mongo DB

NoSQLにしては検索能力が高いオープンソースのNoSQLです。
AWS内ではDocument DBという名称のサービスで利用できます。

### Dynamo DB - AWS

AWSの主力NoSQLデータベースで、基本的なNoSQLに加えINSERT/MODIFY/REMOVEの各イベントでDynamo Streams（トリガー）が動くので実装の幅が広がります。

## 全文検索エンジン

### [Elasticsearch（エラスティックサーチ）](https://www.elastic.co/jp/elasticsearch)

- オープンソース
- API検索

全文検索の代表格。非常に高速で柔軟な検索ができる。
AWS内においては、Elasticsearchを元にしたOpenSearch（オープンサーチ）というサービスで展開されている。

### [Algolia（アルゴリア）](https://www.algolia.com/)

- SaaS
- API検索

SaaSとして気軽に利用できる全文検索エンジン。

### [meilisearch（メイリサーチ）](https://www.meilisearch.com/)

- オープンソース
- API検索

Elasticsearchには敵わないが、軽量なため用途によってはこちらが最適な場合あり。
Lambdaにも実装可能ではあるが、常時ファイル書き込みするため料金的にニーズに合わなくなってしまうのでサーバーで運用するのが無難。
モノは良いのだが、SaaSで使うならElasticsearch、個人ブログならAlgoliaと絶妙に使い所がないシロモノ。
SQLiteのようにアプリへの組み込みには良いと思います。

## DWH（データウェアハウス）

基本的にはカラム型であり大規模な集計には向くが、MySQLのような使い方はできない。  
また、一発ナンボの世界なのでMySQLのようにユーザー入力で都度検索していると莫大な請求になります。

### BigQuery - GCP

Googleならこれを使用します。割と一般的に使われているよう。

### RedShift - AWS

AWS最高峰。クラスター付きでかなりのお値段になります。

### Athena - AWS

S3に溜めたデータをクエリできるためAWSの中では一番現実的な選択肢になると思います。

### S3 Select - AWS

S3のデータをちょっと検索するのに使用します。
